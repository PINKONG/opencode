# Sidecar External Context Implementation Plan

Status: implemented baseline. The runtime implementation and focused verification are complete; packaged cross-platform and real cross-site iframe checks remain release gates.

## Goal And Constraints

The host sends only `{ type: "wiscode.context.update", data }`. No handshake, host version, session ID, context.required handler, or receipt listener is required. WisCode owns validation, routing, persistence, and concurrency.

- Preserve existing embed_session authentication and workspace/session authorization.
- Install a lightweight receiver before async embed initialization; activate only in explicit embed mode inside an iframe.
- Check parent source and pin the first fully valid origin; reject opaque origins. The host origin is not pre-registered.
- No receipts are emitted in this version. Never put metadata in URLs.
- Complete replacement; `{}` is an explicit clear, distinct from no received value.
- Keep latestHostContext in this iframe only. Apply it automatically when the active Router session changes. Do not copy restored data from unrelated sessions.
- Refresh reuses the current session's durable snapshot without host confirmation. No localStorage or global cross-iframe cache.
- Preserve diagnostics category filtering and the unrelated local bun.lock change.

## Task 1: Protocol And Persistence Tests

Add Core/HTTP API tests for object validation, replacement/clear, resource limits, authorization, revision-zero first write, CAS, idempotent replay, reused IDs, stale versions, and session deletion. Add App bridge tests for source/origin checks, rejected payload diagnostics, and no-handshake operation. Run focused tests from package directories and confirm missing implementation fails.

## Task 2: Schema, Migration, And Storage

Add a session_external_context table with snake_case fields and a session foreign key. Store the current value, revision, source, last instance/version/request/hash/result, and timestamp. Generate schema.gen.ts and migration.gen.ts using the repository migration workflow from packages/core; do not edit generated files manually.

Implement atomic CAS and complete replacement. Canonically hash the internal request excluding requestId. Replay the most recent matching request, reject conflicting reuse, and reject stale requests. Delete records with sessions in the same transaction or by foreign-key cascade. Test service restart and explicit deletion.

## Task 3: Authenticated API

Add PUT/GET/DELETE /session/:sessionID/external-context through the existing session authorization chain. Validate workspace/location access and all data limits server-side. API fields source, instanceId, contextVersion, requestId, and expectedRevision are generated by WisCode, not required from the host. Return structured failures without full metadata or credentials.

## Task 4: Early Embed Receiver And Bridge

Install the receiver before Router/SDK async initialization and transfer captured values without losing updates. Schema limits are 256 KiB UTF-8 JSON, depth 20, 10,000 total object keys, and 10,000 elements per array. Reject invalid JSON-compatible values rather than coercing or truncating them.

Pin event.origin only after full validation and parent source checks. Do not emit receipts or implement ping/ready/context.required. Test valid load-time sending as well as pre-listener loss boundaries. Keep normal Web/Desktop untouched.

## Task 5: Router Binding, Queue, And Recovery

Use active Router session parameters as authority; server-sync only verifies entity state. Capture target session when enqueueing writes. Keep latestHostContext, including explicit {}, and automatically apply it to a newly active session. Before a session exists keep only the newest pending value and save it after a session is available.

Generate internal request IDs/versions and serialize writes. Retry transient network failures at most three times with the same request; do not blindly rebase CAS conflicts. Late responses cannot alter a different active session. Preserve confirmed snapshots on failure and surface unsaved state locally. Embed prompt submission waits for already queued binding attempts, never for future host messages. No host receipt is required.

Refresh destroys memory but restores the active session's durable snapshot without awaiting-host. If this iframe has never received host data, switching to another session reads only that session's own snapshot. Test all lifecycle branches and clarify that refresh can lose unsaved pending data.

## Task 6: Shared Model Context And Skill Guidance

Read committed snapshots at provider-request assembly time through a shared loader/renderer. Integrate Legacy SessionPrompt and V2 runner independently. Stable JSON serialization escapes literal `<` as `\u003c` before wrapping in wiscode_external_context. Keep complete scripts and reject/report model budget overflow without silent truncation. Do not apply a diagnostic-reader line limit as an API or model limit.

Skip empty/no-context blocks. Keep data out of user history. Add `docs/wiscode-sidecar-skill-context.md` with the model data flow, field paths, missing-data behavior, security rules, and the WisForm event assistant example. Metadata is untrusted source material, never tool permissions or executable instructions. Legacy tests use the real prompt route with a simulated provider; V2 tests directly drive the runner until V2 is routed live. Both injection paths must assert the final provider request contains the rendered block.

## Task 7: Diagnostics, SDKs, And Verification

Emit metadata-only context.* diagnostics and honor existing categories. Do not turn on rawPayloads or llmContent. Confirm enabled model-content logs may include the external context by existing rules.

Regenerate packages/client with bun run generate, then the legacy SDK with packages/sdk/js/script/build.ts. Verify OpenAPI and generated signatures. Run focused tests and bun typecheck from affected package directories; run git diff --check.

Manual release gates: real cross-site iframe load-time send, no host response listener, update/clear, refresh without resend, session switch, absent data, auth failure, and packaged Windows/macOS/Linux sidecar. Record actual results before declaring implementation complete.
