## 失败与复核

以下问题在合并前 HEAD 的独立工作树、同一 Bun 1.4.4 及共享安装依赖下复现，不在本次合并混修：

- Core `Config > does not load legacy config.json files`：documents 期望 0，实际 1。
- Branding `docs use wiscode config and storage paths` 和 `cli-facing guidance uses wiscode command examples`：已有文档路径和源码匹配断言问题。
- App 的 custom-elements 引用文件、公共资源镜像、自定义 provider 文档链接和 `pa-PK` 语言检测四项。上述四项在原系统 Bun 1.4.2 下也复现。
- App 全量合跑额外出现两个 `authFromToken` 和一个 session-route 断言失败：`use-providers.test.ts` 的 `mock.module("@/utils/base64")` 泄漏到后续测试。合并前全量发现顺序未触发，但按 `use-providers` → server → session-route 顺序运行会复现同样三项失败；合并后 server/session-route 单独运行 11/11 通过。

其他验证波动：

- 扩展回归中 processor 的 `preserve text start time` 触发默认 5 秒超时。整个 processor 文件以 30 秒限制复跑 18/18 通过，随后该用例在默认 5 秒限制下复跑通过（约 963ms）。不把初次运行报告成全绿。
- BMAD 首轮的远端状态查询导致迁移测试超时，已终止该轮。使用仅当前命令生效的 localhost 不可用代理，使远端检查快速失败后，完整 BMAD 门禁 36/36 通过。未修改 vendored 源码或跳过初始化；这轮验证覆盖远端不可用时的本地初始化行为，不证明远端更新服务可达。
- Session 的 V2 projector 用例是既有跳过，不计入通过数。
